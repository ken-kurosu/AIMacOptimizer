# AI Mac Optimizer — 残作業ハンドオフ手順書（代行者向け）

対象: この作業を **初めて担当する人**
作成: 2026-07-21
前提知識: ターミナル(zsh)で1行コマンドをコピペ実行できること。Mac操作ができること。

このアプリ「AI Mac Optimizer」は、Macを軽くするメニューバー常駐アプリ（無料版＋有料Pro版）です。
アプリ本体・配布・ランディングページ・課金の裏側（サーバー）は**すでに完成して動いています**。
残っているのは下の**2つの作業だけ**です。どちらも「動くと分かっているものを、実際に一度通して確認する／再設定する」作業です。

- **作業A**: アプリを配布用にパッケージ化するための「公証(こうしょう)」の鍵を、新しいPCに再登録する
- **作業B**: 「お金を払う → ライセンスキーが自動で届く → アプリがPro版になる」の一連の流れを、本番で一度だけ実際に通して確認する

作業Aと作業Bは**独立**しています。どちらから始めてもOKです。

## 用語ミニ辞典（最初に読むと理解が早い）

| 用語 | かんたんな意味 |
|---|---|
| **公証 (notarization)** | Appleにアプリを送って「悪意のあるソフトではない」と検査・承認してもらう手続き。これを通さないと、配布したアプリを利用者が開くとき「開発元を確認できません」という警告が出て、多くの人が使うのをやめてしまう。 |
| **notarytool** | Appleに公証を依頼するための、Mac標準のコマンドラインツール（`xcrun notarytool`）。 |
| **App用パスワード** | Apple IDの通常パスワードとは**別物**。ツール(notarytool等)から安全にAppleへアクセスするための専用パスワード。2ファクタ認証のApple IDでは、通常パスワードを直接ツールに入れられないため、これを発行して使う。 |
| **キーチェーンプロファイル** | 上記のApple ID＋App用パスワードを、Macの安全な保管庫(キーチェーン)に名前を付けて保存したもの。今回の名前は `AIMacOptimizer`。一度作れば、以後コマンドはこの名前を指すだけで公証できる。 |
| **Stripe** | クレジットカード決済サービス。利用者はStripe経由で支払う。 |
| **Webhook (ウェブフック)** | 「支払いが完了した」等の出来事を、Stripeが自動でこちらのサーバーに通知する仕組み。 |
| **ライセンスキー** | `AIMAC-xxxxx...` という文字列。支払い後に自動生成され、購入者にメールで届く。アプリに貼るとPro版になる。 |
| **本番(Live)モード / テストモード** | Stripeには「本物のお金が動く本番」と「練習用のテスト」の2モードがある。両者は完全に分離している（後述の重要注意）。 |

# 作業A：公証プロファイルの再登録

## これは何の作業か
このアプリを配布ファイル(.dmg)にする際、Appleの「公証」を通す必要があります。公証を依頼するには、Macのキーチェーンに `AIMacOptimizer` という名前の認証情報が保存されている必要があります。

## なぜ今これが必要か
黒須さんがPCを新しく買い替えたため、以前のPCにあったこの認証情報が新PCに引き継がれず、消えてしまいました。
そのため**今のままだと、次にアプリを更新して配布ファイルを作ろうとすると公証が失敗します**。
※ すでに配布中の現行バージョン(build14)は公証済みなので、利用者への影響は今のところありません。「次にアプリを直したとき」に備えて、先に直しておく作業です。

## 事前に用意するもの
- **Apple Developer Programに登録しているApple ID**（チームID `AUJDN6C7VB` のアカウント）。
  - おそらく `kurosu@i-kasa.com` ですが、**必ず確認してください**（確認方法は手順1）。
- そのApple IDのログインパスワード（App用パスワード発行時に一度使う）
- そのApple IDに紐づくスマホ等（2ファクタ認証のコード受信用）

## 手順

### 手順1. どのApple IDか確認する
ブラウザで https://developer.apple.com にアクセスし、右上からサインイン状態を確認。
**「KEN KUROSU」「Team ID: AUJDN6C7VB」** と表示されるApple IDが正解です。
このメールアドレスを控えてください（以降 `＜あなたのAppleID＞` と書きます）。

### 手順2. App用パスワードを発行する
1. ブラウザで https://account.apple.com にアクセスし、手順1で確認したApple IDでサインイン
2. **「サインインとセキュリティ」→「アプリ用パスワード」** を開く
3. 右の **「＋」（またはApp用パスワードを生成）** をクリック
4. 名前を聞かれるので `notarytool` と入力（何でもよい）
5. 画面に **`xxxx-xxxx-xxxx-xxxx`** という形式のパスワードが表示される
   → これを**その場でコピー**（この画面を閉じると二度と表示されません。閉じたら作り直し）

> ⚠️ よくある失敗：Apple IDの**通常のログインパスワード**を次で入れてしまう → 必ず失敗(401エラー)します。上でコピーした `xxxx-xxxx-xxxx-xxxx` を使ってください。
> ⚠️ 「アプリ用パスワード」の項目が見当たらない → そのApple IDが2ファクタ認証OFF、またはDeveloper登録アカウントと別物の可能性。手順1に戻って確認。

### 手順3. キーチェーンに登録する
ターミナルを開き、以下を実行（`＜...＞` の2箇所を実物に置き換える。チームIDはそのままでOK）：

```bash
xcrun notarytool store-credentials "AIMacOptimizer" \
  --apple-id ＜あなたのAppleID＞ \
  --team-id AUJDN6C7VB \
  --password ＜手順2でコピーしたxxxx-xxxx-xxxx-xxxx＞
```

**成功すると** `This process stores your credentials securely in the Keychain.` に続き
`Validating your credentials... Success. Credentials validated.` と表示されます。

### 手順4. 登録できたか確認する
```bash
xcrun notarytool history --keychain-profile AIMacOptimizer
```
- **成功**: 過去の公証履歴の一覧（または空でもエラーなし）が表示される
- **失敗**: `No Keychain password item found for profile: AIMacOptimizer` → 手順3が未完了。やり直す

これが通れば作業Aは完了です。以降、アプリを更新して `scripts/build_dmg.sh` を実行すれば、公証まで自動で通るようになります。

### （任意）手順5. 実際にビルドまで通して最終確認
時間があれば、実際に配布ファイルが作れることまで確認できます：
```bash
cd ~/AIMacOptimizer
swift build -c release        # 先にビルドだけ通す(数十秒)
bash scripts/build_dmg.sh     # 署名→公証→DMG作成まで自動。数分かかる
```
最後に `Accepted` と出て `build/release/` に `.dmg` ができれば完璧です。
（※これは確認用。実際の配布・アップロードは黒須さん/開発者が別途行います）

# 作業B：購入〜ライセンス発行の実地テスト

## これは何の作業か
「利用者がお金を払う → ライセンスキーが自動で作られてメールで届く → アプリに貼るとPro版になる」——
この一連の流れを、**実際に一度、自分で通して確認する**作業です。

## 仕組み（全体像）
```
利用者が支払う(Stripe)
      │
      ▼  Stripeが「支払い完了」を自動通知(Webhook)
サーバー(Cloudflare Worker)
  ・ライセンスキー AIMAC-xxxx を自動生成
  ・購入者のメール宛に自動送信(Resend)
  ・購読状態をデータベース(KV)に記録
      │
      ▼  購入者がメールのキーをアプリに貼る
アプリがPro版になる
  ・キー自体の正しさ(署名)をオフライン検証
  ・月額の人は、アプリがオンラインで「まだ購読中か」を自動確認(/validate)
```
このサーバー側の仕組みは**すべて構築・デプロイ済みで、単体では正常応答することを確認済み**です。
ただし、**実際の「支払い」を一度も通したことがありません**（データベースに購入記録が0件）。
そのため本番集客の前に、一度だけ本物の流れを通して「本当に最後までつながっているか」を確認します。

## ⚠️ 最重要の注意：なぜ「テストモード」ではなく「本番」でやるのか
Stripeには練習用の「テストモード」がありますが、**今回はテストモードが使えません。** 理由：
- サーバーは、Stripeからの通知が**本物か偽物かを「署名」で検証**しています。
- この署名の照合鍵は **本番モード用のものが1つだけ**サーバーに登録されています。
- テストモードの通知は**別の鍵**で署名されるため、サーバーが「偽物」と判断して弾いてしまい、キーが発行されません。

→ よって、**本番モードで実際に¥480を支払い、確認後に解約＋返金する**のが、一番確実で安全な方法です（実質の負担0円）。
（テストモードでやりたい場合はサーバーの鍵の入れ替え等が必要になり、初めての人には非推奨です）

## 事前に用意するもの
- Stripeダッシュボードにログインできる権限（黒須さんに共有してもらう）
- 本物のクレジットカード（自分のものでOK。最後に返金するので実質0円）
- メールを受け取れる自分のメールアドレス

## 手順

### 手順1. Stripeが「本番モード」になっているか確認
Stripeダッシュボード(https://dashboard.stripe.com) にログイン。
画面のモード切替が **本番(Live)** 側になっていることを確認（テストモードのトグルがOFF）。

### 手順2. 実際に月額プランを購入する
以下のリンクを開いて、自分のカードで購入します（月額¥480）：
```
https://buy.stripe.com/4gMeV6bN6fS61hv6XqgYU00
```
- メールアドレス入力欄には、**自分が受信できるメールアドレス**を入れる（ここにキーが届く）
- カード情報を入れて支払いを完了する

> 買い切り(¥4,980)でも確認できますが、返金しても手数料の扱いが月額よりやや面倒なので、**月額¥480での確認を推奨**します。

### 手順3. サーバーが通知を受け取ったか確認（Stripe側）
Stripeダッシュボード → **開発者 → Webhook** → 登録されているエンドポイント(`aimac-license-webhook...` 宛)を開く。
「最近のイベント」に **`checkout.session.completed`** が届いていて、**ステータスが 200 (成功)** になっていればOK。
（もし 4xx/5xx エラーなら、キー発行に失敗しています。その旨を開発者に連絡してください）

### 手順4. ライセンスキーのメールが届いたか確認
手順2で入力したメールアドレスの受信箱を見る。
- **件名: 「AI Mac Optimizer ライセンスキー」** のメールが届く（迷惑メールフォルダも確認）
- 本文に **`AIMAC-`** で始まる文字列があります。これがライセンスキー。

### 手順5. アプリに貼ってPro版になるか確認
1. AI Mac Optimizer アプリを起動（メニューバーのアイコンをクリック）
2. **設定タブ → ライセンス → ライセンスキー入力欄** に、手順4のキーを貼り付ける
3. 「有効化」ボタンを押す
4. **緑のチェック**が出て、Pro版の機能（ストレージ削除・スケジュール等）が使えるようになればOK

### 手順6. 後始末（解約＋返金）
確認が終わったら、テスト購入を解約・返金します：
1. Stripeダッシュボード → **サブスクリプション** → 今回の購読を探して **キャンセル**
2. Stripeダッシュボード → **支払い(Payments)** → 今回の¥480を探して **返金(Refund)**

> 月額を解約すると、購読期間の満了後にアプリが自動でFree版に戻ります（アプリがオンラインで購読状態を確認しているため）。この「解約後にFreeへ戻る」挙動も、余裕があれば後日確認できると万全です。

これで作業Bは完了です。**「支払い→キー→Pro化」が本番で一度通った**ことになり、安心して集客・宣伝を始められます。

## 困ったときの連絡ポイント
- 作業Aで `401 Invalid credentials` → App用パスワードの取り違え。手順2からやり直し
- 作業Bで Webhook が 200 にならない / メールが来ない → サーバー側調査が必要。開発者へ連絡
- どちらも判断に迷ったら、勝手に鍵やシークレットを変更せず、状況を開発者に共有してください
